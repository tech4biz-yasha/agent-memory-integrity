Letta archival memory

Letta archival memory was attacked through its own API, the way an agent's user or a planted document would. 4 attacks surfaced in recall, 1 kept out, 1 not applicable.

What this means

These attacks need no store access at all, only the ability to write through the tool's own API: a user, a document, another session. 4 of six surfaced in recall as the user's own memory; 1 were kept out.

A verdict is what the tool did, not an opinion. "Accepted" means it loaded the altered store, raised nothing, and the agent carried on from the altered memory as if it were true. Every cell has a control that proves the edit landed before the verdict counts.

Where the attacker stands

The attacker never touches the store. Every attack is written through the tool's own API, as a user, a document or another session would write it, and recall is asked whether it serves the result as the user's own.

Reproduce this row

Everything runs offline unless the store is a managed cloud service, in which case the row needs a project of your own. The run seeds a fresh store, applies each edit, confirms it landed, reopens the store and records what came back.

pip install agent-memory-integrity
python agmi/full_runner.py --json results/scorecard.json   # every row, this one included
