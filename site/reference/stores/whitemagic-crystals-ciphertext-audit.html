What this means

A third party holding the signed ciphertext but not the key-encryption key runs LocalCrystalStore.verify_third_party() and is told about every one of the ten edits. It is an audit, not the read path: it shows that someone without the plaintext can check the store, not that the agent is stopped from reading an edited record. The row was narrowed to this from a plaintext read after a detached-plaintext case showed the earlier claim was too broad; the maintainer posted that correction to the W3C interop list himself.

A verdict is what the tool did, not an opinion. "Accepted" means it loaded the altered store, raised nothing, and the agent carried on from the altered memory as if it were true. Every cell has a control that proves the edit landed before the verdict counts.

Where the attacker stands

The attacker reads and writes the WhiteMagic store directory, as a mounted volume, a shared disk or a restored backup would allow. He holds no signing key. In the default and audit rows he cannot reach the anchors directory under XDG_STATE_HOME; in the in-store row the commitment sits inside the directory he controls. An attacker who holds a key or the anchors directory is a different measurement and these rows do not speak for it.

Reproduce this row

Everything runs offline. The run seeds a fresh store through the client's own API, applies each edit beneath it, reopens the store and records what came back.

pip install agent-memory-integrity
curl -sL -o crystal_client.py https://raw.githubusercontent.com/lbailey94/whitemagic/273b177b5c59eb3148b721a85683ab929041d246/scripts/crystal_client.py   # sha256 e44b13f2
export AGMI_WHITEMAGIC_CRYSTAL_CLIENT=<path to crystal_client.py>
python agmi/full_runner.py --json results/scorecard.json   # every row, this one included
python -m agmi.agent --target whitemagic-crystals+ciphertext-audit --compose
